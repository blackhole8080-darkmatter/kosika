BUILD WITH UNDERSTANDING
A little language. Clear boundaries.
A practical guide to your first Kosika workflow.
01 / DECLARE
Start with a contract.
Records describe the shape of data. A model declares what it accepts and returns. Kosika checks these boundaries before passing results to the next step.
record Question { text: Text }
record Answer { text: Text }
model writer { input: Question output: Answer }
02 / COMPOSE
Make every step visible.
Use use_model for a typed model response, ask for a bounded agent, or call to compose another workflow. Import local modules and explicitly export the declarations others may use.
workflow main(question: Question) -> Answer {
  step respond {
    let result: Answer = use_model writer(
      text: question.text
    )
    return result
  }
}
03 / VERIFY
Test the behavior. Keep the evidence.
Check validates syntax, records, workflow calls, and capabilities. Run workflow executes with your input records and scripted model responses. Replay validates the captured trace and returns the recorded result without calling a model or tool.
The workbench boundary
This interface runs fixture models and built-in read-only mock tools. An explicitly host-configured local model is optional. The browser cannot choose endpoints, shell commands, arbitrary files, or external MCP servers.
Model fixture shape
{
  "writer": [
    { "text": "Hello." }
  ]
}
Each array entry is the next response. Use one per model request. A missing response fails instead of inventing an answer.
Keep your work
Drafts are saved in this browser when local storage is available. Export a workspace to keep your files, inputs, and fixtures together. Download a trace to retain run evidence.
